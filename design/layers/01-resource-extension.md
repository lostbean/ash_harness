# Layer 01 — `AshHarness.Resource` extension

Adds agent-facing metadata to an Ash resource. **Does not modify any Ash
behavior.**

## Purpose

Lets a resource author declare:

- A natural-language **description** of what the resource represents.
- Per-action **hints** (when to use, when not to use).
- **Traversable** relationships the agent may navigate.
- **Hidden attributes** that should be excluded from agent context.

These are read by `AshHarness.ContextRenderer` and `AshHarness.ToolGen`.
Without them, an agent can still operate on a resource — descriptions
fall back to the module name and all relationships are treated as
non-traversable.

## DSL

```elixir
defmodule MyApp.Ticketing.Ticket do
  use Ash.Resource,
    domain: MyApp.Ticketing,
    extensions: [AshHarness.Resource]

  agent_annotations do
    description "A work item tracking a bug, feature, or task"

    hint :open_ticket, "Use when someone reports a new issue."
    hint :assign,      "Delegate work to a team member."
    hint :resolve,     "Only works on in-progress tickets."

    traversable        [:project, :comments]
    hidden_attributes  [:internal_notes, :audit_hash]
  end

  # … Ash actions, attributes, etc. unchanged …
end
```

## Schema

```elixir
agent_annotations do
  # Required.
  description :: String.t()

  # Optional, default [].
  traversable :: [atom()]

  # Optional, default [].
  hidden_attributes :: [atom()]

  # Zero or more `hint` entries.
  hint :action_name :: atom(), text :: String.t()
end
```

## Hint entity

```elixir
defmodule AshHarness.Resource.Hint do
  defstruct [:action_name, :text]

  @type t :: %__MODULE__{
    action_name: atom(),
    text: String.t()
  }
end
```

## Introspection — `AshHarness.Resource.Info`

Generated by `Spark.InfoGenerator`. All functions take a resource module
or DSL state.

```elixir
@spec description(Ash.Resource.t()) :: String.t() | nil
def description(resource)

@spec hints(Ash.Resource.t()) :: [Hint.t()]
def hints(resource)

@spec hint_for(Ash.Resource.t(), atom()) :: String.t() | nil
def hint_for(resource, action)

@spec traversable(Ash.Resource.t()) :: [atom()]
def traversable(resource)

@spec hidden_attributes(Ash.Resource.t()) :: [atom()]
def hidden_attributes(resource)

@spec agent_annotated?(Ash.Resource.t()) :: boolean()
def agent_annotated?(resource)
```

## Compile-time validation (verifier)

`AshHarness.Resource.Verifier` runs after all transformers and validates:

| Check | Error message |
| --- | --- |
| Every `hint` action_name corresponds to an existing action | `"Hint references action :foo, but no such action exists on MyApp.Ticket"` |
| Every `traversable` atom corresponds to an existing relationship | `"Traversable references relationship :bar, but no such relationship exists on MyApp.Ticket"` |
| Every `hidden_attributes` atom corresponds to an existing attribute | `"hidden_attributes references attribute :baz, but no such attribute exists on MyApp.Ticket"` |
| Description is present (declared `required: true` in schema) | Spark default error |

## Transformer (data shaping)

`AshHarness.Resource.Transformer`:

- Persists hints into a map keyed by action name for O(1) lookup at
  context-render time.
- Persists `traversable` and `hidden_attributes` as MapSets (O(1) member
  checks during reachability and rendering).
- Idempotent; re-runnable if other transformers add actions later.

## Behavior on absent extension

If a resource does *not* extend `AshHarness.Resource`:

- `Info.description/1` returns `nil` (renderer falls back to the module's
  short name).
- `Info.hints/1` returns `[]`.
- `Info.traversable/1` returns `[]`. **All relationships are non-traversable
  by default.** This is conservative: if you want an agent to navigate a
  relationship, you opt in.
- `Info.hidden_attributes/1` returns `[]`.
- `Info.agent_annotated?/1` returns `false`.

The reachability graph treats unannotated resources as opaque: in scope,
yes; navigable to neighbors, no.

## Examples

### Minimal

```elixir
agent_annotations do
  description "A user account."
end
```

### Full

```elixir
agent_annotations do
  description "An order placed by a customer. Has at most one shipment."
  hint :place,    "Use when a customer wants to buy items."
  hint :cancel,   "Use only before shipment is dispatched."
  hint :refund,   "Issue a refund to the customer's original payment method."
  traversable      [:customer, :line_items, :shipment]
  hidden_attributes [:internal_score, :fraud_signals]
end
```

## Open questions

- **Should hints support multi-line strings or template variables?**
  v0.1.0: plain strings, no interpolation. If users start writing
  multi-paragraph hints with conditional logic, revisit.
- **Should `hint` allow forbidding an action for the agent (i.e., `forbid
  :destroy`)?** Currently the way to forbid is to leave it out of scope.
  No need for a separate forbid mechanism.
- **Do we want a `hint :default_strategy, "…"` for the resource as a
  whole, distinct from per-action hints?** Defer; if needed, add as a
  separate top-level DSL key, not a hint without an action.
